Current behavior: --stdin accepts any byte 0x00-0xFF and passes raw bytes to crc().
Verified live: CRLF input (b"123456789\r\n") → 0x342, binary bytes → 0x050,
empty stdin → 0x3ff. No test in tests/test_crc10_gsm.py asserts these specific
stdin variants. The current test_cli_stdin only covers the canonical RevEng
vector b"123456789" via subprocess.
